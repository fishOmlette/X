\begin{abstract}
A robot may receive a plan, prediction, or state update that was valid when it
was produced but is no longer safe to use.  What should travel with that result
so the receiving component can check it?  In this note, I review contract-based
and runtime-assurance approaches with that question in mind.  I organize the
review by what each approach protects and identify five recurring interface
gaps: meaning and physical validity; timing; uncertainty and evidence;
implementation and lifecycle compatibility; and recovery authority.  Public
failure reports from the ROS~2 navigation stack illustrate the compatibility
and lifecycle gap.

I then propose an interface-contract framework that records the payload,
metadata, assumptions, guarantees, checks, evidence, and recovery rule for a
transfer.  Required checks must pass before the receiver uses the result;
missing evidence does not count as a pass.  A worked collision-avoidance
condition shows how state age, clock error, and estimation error consume the
available margin, and when a local estimate can be preferable to a more
accurate remote one.  A command trace and failure taxonomy show how the fields
fit together.  The central finding is that validity depends on more than the
payload: the receiver also needs the timing, assumptions, and evidence behind
it.  The framework turns those dependencies into explicit interface checks.
\end{abstract}

\noindent\textbf{Keywords:} Multi-robot systems, assume--guarantee contracts,
runtime assurance, runtime verification, ROS~2, age of information.
