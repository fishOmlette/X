\section{Introduction}

Autonomous systems increasingly use runtime layers to monitor safety, performance, or mission properties and intervene during execution. Existing work includes mission-level runtime assurance for autonomous driving~\cite{missionrta_ad}, modular runtime assurance for robotics~\cite{soter}, and predictive runtime verification, enforcement, and monitoring~\cite{pinisetty_re,pinisetty_rv,sankar_prm,radics}. Prediction is attractive because the extra lead may permit a completion-preserving recovery instead of an emergency stop.

We ask: \emph{when does predicting loss of feasibility actually outperform reacting to it?} A predictive assurance layer must be built, tuned, and certified. Comparing it only with an unpadded reactive trigger does not show that prediction is necessary, because a fixed trigger margin is a simpler way to intervene early. The fixed margin should therefore receive a comparable tuning budget.

The analysis in Section~\ref{sec:analysis} shows that a projected time-to-infeasibility trigger is a reactive trigger with a rate-scaled margin. It identifies the lead-time band in which an earlier trigger can change a recovery outcome and the rate variation needed to distinguish that trigger from one fixed margin across cases. Sections~\ref{sec:method}--\ref{sec:exp} examine these conditions in a two-robot kinematic simulation. Exploratory sweeps against a fixed pad selected on the same runs locate a narrow boundary; a seed-disjoint evaluation with equal tuning budgets is planned.
